Три фазы

Red

Пишем тест который заведомо падает. Фиксируем желаемое поведение до кода.

Green

Пишем минимальный код чтобы тест прошёл. Не думаем о красоте — только о результате.

Refactor

Улучшаем код не меняя поведение. Тесты гарантируют что ничего не сломали.

Рефакторинг без тестов — это надежда. Рефакторинг с тестами — это уверенность

Почему это важно для агента

Без тестов

  • Рефакторит — что-то ломает
  • Не знает что именно сломалось
  • Пишет код поверх сломанного
  • Уверенно говорит "всё готово"

С тестами

  • Рефакторит шаг за шагом
  • После каждого шага — запускает тесты
  • Красный → сразу откатывает и думает
  • Зелёный → уверенно идёт дальше

Тесты — это не про проверку кода. Это про свободу менять код когда угодно

Задача — разделяем auth на два модуля

До

auth/
  auth.module.ts
  auth.controller.ts
  ← логин + регистрация
  ← работа с пользователем
  auth.service.ts
  ← JWT токены
  ← создание юзера
  ← поиск по email

После

auth/
  auth.module.ts
  auth.controller.ts ← логин, регистрация
  auth.service.ts    ← только JWT

users/
  users.module.ts
  users.controller.ts
  users.service.ts
  ← создание юзера
  ← поиск по email

Тесты авторизации страхуют каждый шаг — если что-то сломается при разделении, сразу увидим

Порядок работы с Claude

1

Убеждаемся что тесты зелёные

Запускаем npm run test — все тесты авторизации должны быть зелёными до начала рефакторинга.

2

Даём задачу Claude

Просим разделить модуль. Явно говорим: после каждого шага запускать тесты и не двигаться дальше если красные.

3

Наблюдаем за циклом

Claude переносит код, запускает тесты, видит красный — откатывает или правит. Не вмешиваемся.

4

Финальная проверка

Все тесты зелёные. Два отдельных модуля. Поведение не изменилось — только структура стала чище.
